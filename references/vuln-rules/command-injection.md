# 命令注入

**适用**：被校验的主张是命令注入，且命令执行点以字符串或数组形式调用操作系统命令/脚本。

命令注入的核心判定依据是：**可控输入能否改变命令语义或执行额外命令**。不要仅凭执行形式（字符串 vs 数组）下结论，须按实际内容逐跳核实。

## 1. 参数/字符串直接可控

执行命令的参数来自外部可控输入时，关键看参数能否改变命令语义：

- **确认（是漏洞）**：可控参数到达命令执行点且无有效约束，能构造改变命令行为的 PoC：
  - 高危参数注入：`-o /path/output.txt`、`--output=` 等可覆盖任意文件或指定任意路径
  - 空格攻击：参数内注入空格改变命令行为（如 `rm` 经空格传入额外路径删除非目标文件）
  - 压缩包文件名解析：解压时文件名的空格或 `-` 开头被解析为命令参数
- **无法确认**：参数是否到达执行点、校验是否覆盖存在不可补缺口。

## 2. 数组方式执行命令

数组执行 ≠ 无注入，须按实际内容判定：

- 数组内容指向脚本文件（`script.sh`、自定义脚本路径）时：
  - **确认（是漏洞）**：找到并加载该脚本，脚本内外部参数能导致任意命令执行。
  - **无法确认**：未找到对应脚本--不得下"不存在命令注入"结论，标为无法确认、需人工审查。
- 数组元素直接是命令与参数：按「1. 参数/字符串直接可控」判定可控元素能否改变命令语义。
