- 环境变量表示文件或目录路径：攻击者不可控，不计为 Source（除非能举证可控）
- 子模块内未发现认证鉴权：默认由其他组件承担，不认定为认证鉴权缺失（除非能举证整条调用链上均无认证鉴权）
- URL 路径段拼接：参数来源于 URL 路径段（path 部分，非 query/body/header）又拼接到其他 URL 的，框架已统一处理，不视为漏洞
- CRLF 注入：`header.put(key, value)` 等 HTTP header 设置操作，底层框架已统一处理 CRLF 过滤，不视为漏洞
- 查询参数注入：`params.put(key, value)` 等查询参数设置操作，底层框架已统一处理，不视为漏洞
- 资源标识作存在性判断或查询后返回：用户提供的资源标识（ID、编号）仅做存在性判断或查询，查不到即返回、不进入注入类操作路径的，不认为是漏洞
- 敏感信息认定：仅明文或加密的认证凭据类信息（密码、Token、密钥、证书私钥、Cookie 等）、电话号码、邮箱地址视为敏感信息；用户名、昵称、ID、地址、非私钥的证书字段等不认定。**但当数据内容无法确定时（请求 body 结构未定义、data/msg 等通用容器内容不可追溯），按敏感信息处理**
